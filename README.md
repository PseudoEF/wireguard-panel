# wg-panel

Веб-панель для WireGuard на Windows 10: создание клиентов по имени (`client-01`,
`client-02`, …), выдача `.conf` и QR-кода, статистика онлайн/трафика, отключение
и удаление.

> Публичная версия исходников. Ключи, база клиентов, логи и собранный установщик
> в репозиторий не входят. Лицензия пока не выбрана; код опубликован для
> просмотра и портфолио.

## Установка на сервер — один файл

Всё (код панели, скрипты, обёртка службы WinSW) упаковано в **`dist/wg-panel-setup.ps1`**.
WireGuard и Python установщик сам скачает с официальных сайтов, поэтому серверу нужен интернет.

1. Скопировать `wg-panel-setup.ps1` на сервер (например, на рабочий стол через RDP).
2. Правый клик → **«Выполнить с помощью PowerShell»**. Скрипт сам запросит права
   администратора.
3. Он проверит сервер, покажет план и спросит `y`, затем спросит пароль для панели.
4. В конце покажет адрес панели: `https://<IP>:8443`.

Без вопросов, одной командой (пароль будет сгенерирован и показан в конце):

```powershell
powershell -ExecutionPolicy Bypass -File .\wg-panel-setup.ps1 -Yes
```

Параметры: `-InstallDir C:\wg-panel`, `-Endpoint 1.2.3.4`, `-WgPort 51820`, `-PanelPort 8443`,
`-Subnet 10.8.0.0/24`, `-AdminPassword ...`, `-Yes`.

**Обновление:** запустить новый `wg-panel-setup.ps1` поверх. Ключи, клиенты, порты и пароль
сохранятся.

**Если у хостера есть свой фаервол** в личном кабинете, открыть там UDP 51820 и TCP 8443.

### Сборка установщика (на машине разработчика)

Готовый `dist/wg-panel-setup.ps1` в публичный репозиторий не добавлен.
Для сборки нужен `tools/winsw.exe` из WinSW v2.12.0 (WinSW.NET461.exe,
SHA-256 `b5066b7bbdfba1293e5d15cda3caaea88fbeab35bd5b38c41c913d492aadfc4f`).
Скачайте его с <https://github.com/winsw/winsw/releases> и положите в `tools/`,
затем:

```bash
python build_bundle.py    # -> dist/wg-panel-setup.ps1
```

## Почему RDP не сломается

- В серверном конфиге у пиров только `/32` и нет `0.0.0.0/0`, поэтому маршруты VPS
  не меняются и kill-switch WireGuard не включается.
- В фаервол только **добавляются** два разрешающих правила (группа `wg-panel`),
  существующие не меняются.
- NAT создаётся только для подсети VPN (`10.8.0.0/24`). Если на сервере уже есть другой
  NetNat (Docker или Hyper-V), скрипт его не трогает и NAT не создаёт.
- До любых изменений проверяется, что порты свободны и не совпадают с RDP, а подсеть
  не пересекается с существующими адресами.
- Откатить всё можно одной командой: `.\uninstall.ps1`. Она удаляет только то,
  что поставил install; ключи в `data` остаются.

## Исключения: сайты напрямую, мимо VPN

У каждого клиента есть кнопка «Маршруты». Туда вписываются IP, подсети или домены
латиницей (кириллические `.рф` не принимаются, для них нужно указать IP). Там же
галочка «локальные сети напрямую».

- Работает на стороне клиента через `AllowedIPs`. После изменения клиенту нужно
  **заново выдать конфиг** (QR или .conf), в списке будет пометка «конфиг устарел».
- IP доменов определяются с VPS в момент выдачи. Если у сайта за CDN сменились IP,
  тоже появится «конфиг устарел».
- В QR помещается примерно 5–8 исключений (вместе с локальными сетями). Если больше,
  выдаётся только файл.

## NAT (интернет для клиентов) и перезагрузка

В Windows 10 NAT (`New-NetNat`) работает только при установленных компонентах Hyper-V.
Если их нет, установщик:

1. Включает компоненты Hyper-V, **но отключает запуск самого гипервизора**
   (`bcdedit /set hypervisorlaunchtype off`). NAT работает и так, поэтому подходит VPS
   без вложенной виртуализации. Проверено на тестовой виртуалке.
2. Если на диске включён BitLocker, приостанавливает его на одну перезагрузку. Иначе
   после изменения загрузчика Windows спросит ключ восстановления, а на VPS без консоли
   это потеря доступа.
3. Ставит разовую задачу планировщика `wg-panel-resume` и просит перезагрузку
   (с `-Yes` перезагружает сам через 30 секунд).
4. После загрузки задача сама доделывает NAT и удаляет себя. Итог появляется файлом
   **«wg-panel - итог установки.txt» на рабочем столе**, подробный лог лежит
   в `logs\resume.log`.

Побочный эффект: появится адаптер `vEthernet (Default Switch)`. Это внутренняя сеть
Hyper-V, на RDP и основную сеть он не влияет.

На Windows 10 Home компонентов Hyper-V нет, там NAT не включится: клиенты подключатся,
но без интернета.

## Обслуживание

| Что | Команда |
|---|---|
| Сменить пароль | `.venv\Scripts\python -m app.init_panel --set-password`, затем `Restart-Service wg-panel` |
| Логи панели | `logs\wg-panel.out.log`, `logs\wg-panel.err.log` |
| Логи WireGuard | `"C:\Program Files\WireGuard\wireguard.exe" /dumplog` |
| Состояние туннеля | `& "C:\Program Files\WireGuard\wg.exe" show` |
| Перезапуск | `Restart-Service wg-panel` |
| Удалить всё | `C:\wg-panel\uninstall.ps1` (ключи в `data` остаются; `-PurgeData` удалит и их) |
| Бэкап | папка `data` (ключи сервера, база клиентов) |

Статистика трафика считается с момента запуска туннеля: после перезагрузки VPS
счётчики обнуляются. «Последний раз онлайн» хранится в базе и не сбрасывается.

## Локальная проверка без WireGuard

```bash
export WGPANEL_MOCK=1 WGPANEL_DATA=/tmp/wgdata
python -m app.init_panel --endpoint 127.0.0.1
python run.py   # https://127.0.0.1:8443
```
